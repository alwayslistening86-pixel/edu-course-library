# S21_R097_Interaction_GUI_and_Accessibility - Lesson: Methods of interaction, GUI design, interface styles and accessibility

## Goal
The learner designs an accessible, consistent graphical user interface and chooses interaction and interface styles suited to a device and audience.

## Syllabus items taught here
- R097-1.1d - Methods of user interaction: link touch, voice, camera, keyboard and mouse or joystick input to suitable applications
- R097-1.2a - Graphical user interface (GUI) design: explain consistent layout, colour scheme, house style, typography and white space in an effective GUI
- R097-1.2b - Interface and interaction styles: compare click, touch, voice, motion, drag and drop and feedback/closure, with advantages, limits and non-linear navigation
- R097-1.2c - Accessibility features: select and explain alt text, readability, captions, contrast, resizable text, flexible input and mobile adjustments

## How to teach this
Ask the learner to try navigating a website using only the keyboard, then only by describing what they want aloud. 'What just made that hard?' Use this to introduce that interaction methods, interface design and accessibility are all decisions the designer makes deliberately, not accidents of the software used.

#### R097-1.1d Methods of user interaction
Interaction methods include touch, voice, camera (gesture or image capture), keyboard, and mouse or joystick/controller. Each suits particular devices and audiences: touch suits phones, tablets and kiosks; voice suits hands-free or accessibility contexts; keyboard and mouse suit desktop productivity and precision tasks; controllers suit games consoles. The chosen method affects interface design - a touch interface needs larger, spaced targets; a voice interface needs clear spoken prompts and confirmation. Learners should justify a method against the device and audience in the brief rather than defaulting to touch for everything. Activity: state which interaction method(s) suit a smart-TV cooking app and explain why keyboard and mouse would be unsuitable.

#### R097-1.2a Graphical user interface (GUI) design
A GUI is the visual layer through which a user interacts with a product: menus, icons, buttons, windows and the screen layout that presents them. Good GUI design uses a consistent layout across screens, a limited and purposeful colour scheme, a house style (consistent fonts, icon style and spacing) that reflects brand or purpose, clear typography that is legible at the intended size, and white space to avoid clutter and direct attention. Consistency matters because users learn a pattern once and then expect it to repeat; breaking it (for example moving navigation between screens) increases errors and frustration. Activity: sketch two versions of the same app home screen, one consistent and one not, and identify three inconsistencies in the second.

#### R097-1.2b Interface and interaction styles
Interface styles include command-line (rare in modern consumer products), menu-driven, form-based, graphical/WIMP (windows, icons, menus, pointer) and natural-language/voice. Interaction styles overlay these: click, touch, voice, motion/gesture and drag-and-drop, each needing feedback (confirming an action happened) and closure (confirming a task is complete, for example an order confirmation screen). Non-linear navigation - letting the user jump between sections rather than following one fixed path - is a strength of interactive media over print or broadcast media and should be planned deliberately, not left implicit. Activity: for a recipe app, decide which interaction style suits selecting a recipe versus setting a timer, and explain why they differ.

#### R097-1.2c Accessibility features
Accessibility features include alternative (alt) text for images, readability (plain language, sufficient font size and line spacing), captions and transcripts for audio/video, sufficient colour contrast, resizable text, flexible input (for example keyboard-only navigation or voice control) and layout adjustments for smaller mobile screens. These are not optional extras: excluding them excludes real users, and OCR expects learners to justify accessibility choices against the audience stated in the brief, not add them generically. Teaching activity: take a screen design the learner has sketched and identify two groups of users who might struggle with it as it stands, then propose a specific accessibility feature for each.
