# S22_R097_Conventions_Creativity_and_Creation_Hardware - Lesson: Conventions, creativity and the hardware and software used to create interactive media

## Goal
The learner applies conventions and originality appropriately and explains what hardware and software a designer would use to create a given interactive digital product.

## Syllabus items taught here
- R097-1.2d - Conventions of interactive digital media: apply non-linear navigation, intuitive interfaces and audience suitability conventions
- R097-1.2e - Creativity in interactive digital media: distinguish original, imaginative and derivative work and balance conventions with originality
- R097-1.3a - Hardware used to create interactive digital media: explain why designers use computers, tablets, styluses, monitors, microphones and cameras and the effects of choice
- R097-1.3b - Software used to create interactive digital media: explain web authoring, app creation, authoring tools and kiosk software and the effects of choice

## How to teach this
Show the learner a website with navigation in an unusual place (for example the logo not linking home). 'Why does that feel wrong even though nothing is broken?' Use it to introduce conventions as shared expectations that make products usable, and then contrast with creativity, which is how a designer stands out within those expectations rather than ignoring them.

#### R097-1.2d Conventions of interactive digital media
Conventions are the widely shared expectations users bring to interactive products: non-linear navigation (menus, links, back buttons), intuitive interfaces (icons and labels that behave as expected, such as a magnifying glass meaning search), and general suitability for the stated audience (age-appropriate content, tone and complexity). Following convention reduces the user's learning effort and errors; a product that ignores convention without good reason frustrates users even if it is technically functional. Learners should be able to identify conventions in an existing product and explain what following or breaking one achieves. Activity: identify three navigation conventions on a familiar app and explain what would go wrong if each were reversed.

#### R097-1.2e Creativity in interactive digital media
Work sits somewhere on a scale from wholly original (a new idea, executed independently) through imaginative (a fresh treatment of an existing idea) to derivative (closely copying an existing product's look, content or structure). R097 rewards creativity that still respects conventions and fitness for purpose - originality for its own sake that breaks usability is not rewarded, and copying an existing product's design is not creativity. Learners should be able to describe how their own concept differs from products that inspired it. Activity: take an existing app the learner likes and design one original feature or layout change that improves it for a stated new audience.

#### R097-1.3a Hardware used to create interactive digital media
Creation hardware includes computers (for authoring and editing), tablets and styluses (for sketching or vector drawing), monitors (colour-accurate, sufficiently large for detailed layout work), microphones (for narration or voice content) and cameras (for original photo or video assets). The choice affects quality and workflow: a stylus and tablet speed up freehand concept sketches; a colour-calibrated monitor matters more for graphic-heavy products; a decent microphone matters for e-learning narration. Learners should justify hardware choices against the specific product being made, not list hardware generically. Activity: for an e-learning app with narrated lessons, list two pieces of hardware that matter most and explain why.

#### R097-1.3b Software used to create interactive digital media
Creation software includes web authoring tools (for building websites), app creation/development tools, general authoring tools (for e-learning, kiosks or interactive presentations) and kiosk-specific software. Software choice depends on the target format and platform, the assets already available, licensing, and the skills and time available. Learners should be able to name at least one plausible software category for a stated format and explain what it would let them do that a different category would not (for example an app-creation tool handling touch gestures that a basic web tool does not). Activity: for the museum kiosk brief used earlier, name a suitable software category and explain why general web authoring alone might not be enough.
