# S24_R097_Task1_Evidence_and_Sourcing_Assets - Lesson: Evidencing Task 1 in full, and sourcing assets for creation

## Goal
The learner produces complete Task 1 planning evidence covering every element and asset type, and sources suitable assets by feature, property and licence.

## Syllabus items taught here
- R097-T1b - Task 1 strand 1b: pre-production and planning documentation: know how to plan every element of the product and each asset type in detail
- R097-T1c - Task 1 strand 1c: understanding how assets contribute: know how to explain asset choices against technical properties, audience and conventions
- R097-2.1a - Techniques for sourcing suitable assets: search by feature, property and licence, use libraries and save assets at suitable size and format
- R097-2.1b - Static image assets: types and repurposing: repurpose bitmap and vector images by adjustments, size, filters, transformations and retouching

## How to teach this
Ask the learner: 'If a teacher took away your wireframe, asset table and navigation diagram halfway through building, could someone else finish the product from what's left?' Use the answer to introduce that strand 1b is about completeness across every element, not just quality of one document, and that sourcing assets properly starts the create stage the same way planning finished the plan stage.

#### R097-T1b Task 1 strand 1b: pre-production and planning documentation
Strand 1b (16 marks, the largest single strand in R097) asks for planning across every element of the product: screens/wireframes, colour scheme, text and typography, layout, navigation, GUI features, media/interaction, and the asset table. MB3 evidence is detailed and consistent across all of these, not strong in one area and thin in others; a plan that covers layout brilliantly but has no asset table, or vice versa, cannot reach top marks. Learners should treat strand 1b as a checklist: screens planned, GUI planned, navigation planned, every asset planned. Activity: check the booking-product planning built across S23 against this checklist and identify one gap to fill.

#### R097-T1c Task 1 strand 1c: understanding how assets contribute
Strand 1c (6 marks) asks the learner to explain, for their planned assets, how each one's technical properties support the product's audience, purpose and conventions - for example explaining why a asset needs a transparent background, a particular resolution, or a specific file type, and how that supports the brief. This differs from simply listing assets (which belongs in the asset table for 1b): 1c is the reasoning layer on top of the list. Activity: pick one row from the asset table drafted earlier and write two sentences explaining why its planned properties suit the audience and purpose.

#### R097-2.1a Techniques for sourcing suitable assets
Sourcing techniques include searching by feature (subject matter), by technical property (resolution, format, orientation) and by licence (what use is permitted), using stock libraries, provided client assets or the internet, then saving found assets at a suitable size and format into an organised working folder. Every sourced asset should be checked against the asset table drafted in planning rather than sourced ad hoc, and its licence recorded so permission can be evidenced later. Sourcing an asset that is the wrong resolution or wrongly licensed creates rework, so this step is treated as a skill in its own right, not just downloading. Activity: source (or describe sourcing) one suitable stock image for the booking product and note its licence.

#### R097-2.1b Static image assets: types and repurposing
Static image assets are repurposed (not just used as found) through adjustments (brightness, contrast, colour balance), resizing, filters, transformations (crop, rotate, flip) and retouching (removing blemishes or unwanted elements), so the asset fits the planned use exactly rather than approximately. Repurposing evidence should be visible and deliberate - for example cropping a stock photo to the planned aspect ratio and adjusting its colour to match the product's colour scheme - and connected back to the asset table's specification. Activity: describe how you would repurpose a generic stock photo of a gym so it fits the leisure-centre product's planned colour scheme and crop.

## Explicitly not here
Audio, moving image and interactive asset repurposing (S25), building the product (S26), testing and review (S27-S28).
