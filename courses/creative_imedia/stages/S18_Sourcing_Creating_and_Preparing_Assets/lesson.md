# S18_Sourcing_Creating_and_Preparing_Assets - Lesson: Sourcing, creating, preparing and storing assets

## Goal
The learner sources images and graphics, creates derivative and new assets, prepares them for print by resizing, resampling and rasterising, and stores originals and edited versions in a clear folder structure.

## Syllabus items taught here
- R094-3.2a - Sourcing assets for digital graphics: source images and graphics from the internet, stock libraries or a client library into a working asset folder
- R094-3.2b - Creating and editing assets for digital graphics: make derivative assets by editing sourced images or draw new bitmap or vector assets
- R094-3.2c - Modifying assets for technical compatibility with print: resize, resample, check pixel dimensions and dpi and rasterise vectors for print use
- R094-3.2d - Storing assets: folders and file formats: separate original and edited assets and pick formats that keep quality with or without transparency

## How to teach this
Ask: 'Before you start designing, which jobs must you do to every image so that it will not look bad in the final print?' Emphasise that preparation must be shown as a deliberate step before the graphic is built.

#### R094-3.2a Sourcing assets for digital graphics
Assets are images and graphics. Source them using the internet (with search filters for image size, type and licence), stock libraries (respecting their terms) or the client's own library. Save or download them to a download folder and then copy them to the working asset folder, keeping the original. Obtaining licences and requesting permission is not part of the practical skill here, but recording the source is. Sourcing skill is shown by choosing assets suited to the client and audience: matching style, resolution and licence. Teach: search with keywords from the brief, use the size filter to avoid tiny images, check the licence, and note the URL. Common error: taking the first result at low resolution.

#### R094-3.2b Creating and editing assets for digital graphics
Assets can be created in two ways: editing sourced assets to make a derivative asset (crop, recolour, remove background, combine, retouch) or creating assets with drawing tools as bitmap or vector files (icons, shapes, patterns, illustrations). The practical use of a camera, scanner or graphics tablet is not required. Learners should make original or new image assets so the graphic is not just other people's images placed together. Show the source image and the edited result side by side with a note of what changed. Keep each asset as a separate file before combining in the graphic.

#### R094-3.2c Modifying assets for technical compatibility with print
Prepare assets so they are technically compatible with the intended print product. Resize and resample: check pixel dimensions and dpi for the size the graphic will be reproduced (for example an A5 flyer at 300 dpi needs about 1748 x 2480 pixels for the full page, and a photo covering half the page correspondingly fewer). Resampling changes pixel numbers; enlarging a small image adds no real detail, so choose larger sources instead. Modify image properties as needed (dimensions, resolution, mode). Rasterise vector graphics when they must be combined in a bitmap graphic. Changing colour profiles is not required. Evidence: a screenshot of the image size dialog showing before and after values for each asset. OCR guidance says that for the top band all assets must be prepared and the preparation must be explicit and done before creating the final graphic; if preparation is only implied in the final graphic, MB1 applies.

#### R094-3.2d Storing assets: folders and file formats
Organise storage to separate original and edited assets in different folders (for example originals, edited assets, final exports) and use clear file names. Change file format as needed to retain image quality: save layered masters in the software's own format, use PNG for graphics that need transparency, JPEG for photographs where a small file is acceptable, and avoid repeatedly saving lossy files. Storing originals unaltered lets the learner go back if an edit fails. Evidence: a screenshot of the folder structure. Naming convention example: fernhill_logo_original.png, fernhill_logo_edited_300dpi.png.

## Explicitly not here
