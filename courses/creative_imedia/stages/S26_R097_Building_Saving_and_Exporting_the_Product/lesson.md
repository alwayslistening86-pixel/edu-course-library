# S26_R097_Building_Saving_and_Exporting_the_Product - Lesson: Building the product and saving, exporting and publishing it correctly

## Goal
The learner builds a product from planned components, saves editable native files with version control, and exports in a suitable platform-independent format.

## Syllabus items taught here
- R097-2.2b - Creating the product: templates, navigation, content, playback controls, triggers and behaviours: build master pages, navigation systems, inserted content, playback controls and triggers with behaviours
- R097-2.3a - Saving during creation: native formats and version control: keep editable native files and versioned, well-named saves to allow rollback
- R097-2.3b - Exporting and publishing finished products: export in platform-independent formats that run without specialist software
- R097-T2a - Task 2 strand 2a: creating and preparing the component parts: know how to evidence separate edited assets with effective skills, fit conventions and a supporting range

## How to teach this
Ask the learner: 'If your computer crashed right now, how much work would you lose?' Use the answer to introduce saving discipline (versioning) before covering building the product itself, since the two are taught together in the real workflow.

#### R097-2.2b Creating the product: templates, navigation, content, playback controls, triggers and behaviours
Building the product means assembling the planned components into a working whole: master pages/templates applied consistently, the navigation system linking every planned screen, content (text, images, audio, video) inserted as planned, playback controls added where media plays, and triggers/behaviours (what happens when a user clicks, hovers or completes an action) set up correctly. The build should match the wireframes, asset table and navigation diagram closely; deviating without reason loses marks for fitness for purpose. Learners should build and check navigation as they go, not leave it until the end. Activity: describe the order in which you would build the four screens of the booking product so navigation can be tested as each one is added.

#### R097-2.3a Saving during creation: native formats and version control
Work should be saved in the software's native, editable format throughout creation (not just as a final export), with clear version-numbered file names (for example v1, v2, v3) at meaningful save points, so earlier work can be recovered if a later change goes wrong. This differs from the final export (S below), which is typically not editable. Version control evidence - several saved versions showing progress - is itself assessment evidence of a considered, professional working process. Activity: name three points in building the booking product where you would save a new version and why each point matters.

#### R097-2.3b Exporting and publishing finished products
The finished product is exported or published in a platform-independent format that runs without needing the authoring software installed - for example a website exported to run in any browser, or an app packaged to install and run standalone. Exporting must preserve all planned interactivity, media and navigation; a broken export (missing links, non-playing media) fails fitness for purpose regardless of how good the native file was. Learners should check the exported version works exactly like the native one before considering the product finished. Activity: list two things you would check immediately after exporting the booking product to make sure nothing broke.

#### R097-T2a Task 2 strand 2a: creating and preparing the component parts
Strand 2a (10 marks) asks the learner to evidence each component part created and prepared separately, with effective technical skill, before final assembly - for example a repurposed image, an edited audio clip and a built button, each shown individually with the skill used, and each shown to fit the conventions and audience from planning. MB3 evidence shows a good range of component types prepared to a high technical standard; MB1 evidence shows very few components or basic, unedited assets. Activity: list the separate component parts you would show as evidence for the booking product before final assembly.

## Explicitly not here
Task 2 evidence for the final product and formats (S27), testing and review (S27-S28).
