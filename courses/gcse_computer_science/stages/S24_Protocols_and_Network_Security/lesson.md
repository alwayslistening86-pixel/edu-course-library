# S24_Protocols_and_Network_Security - Lesson: Protocols, network security and the TCP/IP model

#### 3.5.3 Network protocols: Ethernet, Wi-Fi, TCP, UDP, IP, HTTP, HTTPS, FTP, SMTP, IMAP
A **network protocol** is an agreed set of rules that governs how data is formatted, transmitted and received between devices, so that different devices and software can communicate correctly with each other. **Ethernet** is a set of protocols used for wired LANs; **Wi-Fi** is a set of protocols used for wireless LANs. **TCP** (Transmission Control Protocol) manages reliable delivery of data: it breaks data into packets, numbers them so they can be reassembled in the correct order, checks for errors, and requests any lost or corrupted packets be resent. **UDP** (User Datagram Protocol) sends data faster than TCP but with no guarantee of delivery or correct ordering, so it suits situations where speed matters more than perfect reliability (e.g. live video/voice calls, online gaming), where a lost packet is better skipped than waited for. **IP** (Internet Protocol) handles addressing devices and routing packets across networks to the correct destination. **HTTP** (HyperText Transfer Protocol) transfers web pages between a web server and a browser, unencrypted; **HTTPS** (HTTP Secure) is the encrypted version of HTTP, protecting the data exchanged (e.g. passwords, card details) from being read if intercepted. **FTP** (File Transfer Protocol) transfers files between computers on a network. **SMTP** (Simple Mail Transfer Protocol) sends email. **IMAP** (Internet Message Access Protocol) retrieves and manages email that stays stored on a mail server, so it stays synchronised across multiple devices.

#### 3.5.4 Network security: authentication, encryption, firewalls, MAC address filtering
**Network security** methods protect a network from unauthorised access and attack: **authentication** verifies that a user really is who they claim to be, e.g. a correct username and password, before granting access; **encryption** scrambles data using an algorithm and a key so that, if it is intercepted in transit, it is unreadable without the correct key to decrypt it; a **firewall** monitors and controls incoming and outgoing network traffic against a set of rules, blocking traffic that looks unauthorised or suspicious; **MAC address filtering** only allows devices whose network adapter's unique MAC address is on an approved list to connect to the network, blocking any device not on that list even if it has the right password.

#### 3.5.5 The 4-layer TCP/IP model
The **TCP/IP model** describes network communication as four layers, each handling a different part of the job, with protocols operating at particular layers: the **application layer** provides network services directly to software (protocols such as HTTP, HTTPS, FTP, SMTP and IMAP operate here, formatting data appropriately for the application); the **transport layer** manages end-to-end delivery between the two devices communicating (TCP and UDP operate here, splitting data into segments and, for TCP, ensuring reliable, ordered delivery); the **internet layer** handles addressing and routing packets to the correct destination network (IP operates here); the **link layer** handles the actual physical transmission of data over the network hardware/medium (Ethernet and Wi-Fi operate here, converting data into electrical, light or radio signals sent over cables or through the air). Data passed down through these layers when sent, and back up through them (in reverse) when received.
