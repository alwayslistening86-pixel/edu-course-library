# S21_Programming_Languages_and_Translators - Lesson: Programming languages and translators

## Goal
The learner classifies programming languages as low-level or high-level, distinguishes machine code from assembly language, and explains interpreters, compilers and assemblers and when each is used.

## Syllabus items taught here
- 3.4.4 - Classification of programming languages and translators

## How to teach this
Ask the learner: would they rather write instructions for a computer using words like 'IF' and 'PRINT', or as raw strings of 1s and 0s? Have the learner predict the output of every Python example before running it, and run code for real whenever they can. AQA's own exams are set in AQA's pseudo-code, not any specific language; Python (AQA's widely-used reference teaching language) is used here so examples can be run for real and their output verified, but the learner should also be shown the equivalent pseudo-code form for exam-style tracing questions, since Paper 1 code-reading/writing questions are set in pseudo-code with only the constructs taught in 3.2. Binary/hex conversions, storage and sound/image size calculations, Huffman/RLE compression and logic-gate truth tables were computed/verified when this course was built.

#### 3.4.4 Classification of programming languages and translators
Programming languages are classified by **level**: **low-level languages** are close to the computer's own hardware instructions (hard for humans to read, but give precise control and run efficiently); **high-level languages** (e.g. Python, Java) use English-like keywords and structures far removed from hardware detail (much easier for humans to read, write and maintain, and portable across different types of computer, but less directly tied to hardware control). **Machine code** and **assembly language** are both considered low-level: machine code is the pattern of binary instructions a specific processor can execute directly, with no translation needed; assembly language uses short mnemonic instructions (e.g. `ADD`, `LOAD`) that correspond one-to-one with machine code instructions, making it slightly more readable than raw binary but still tied to one specific processor's instruction set. All program code (other than machine code itself) must be **translated** into machine code before a processor can execute it, because the processor can only directly execute binary machine instructions. Three translator types: an **interpreter** translates and executes a high-level program one statement at a time, stopping as soon as it hits an error (useful during development, for quick testing and for interactive/scripting use, but slower to run overall and every run re-translates the code); a **compiler** translates the whole high-level program into a machine-code executable file in one go before it is run, reporting all the syntax errors it finds at once (the resulting executable then runs fast, without needing the source code or the compiler again, but any change to the source means recompiling, and compiling itself can take time); an **assembler** translates assembly language into machine code, using its simple one-to-one mapping between mnemonics and machine instructions. Which to use depends on the situation: an interpreter suits rapid development, testing and scripting; a compiler suits software that will be run many times and needs to run fast, or that must be distributed without its source code; an assembler is used specifically to translate assembly language.
