# S22_Systems_Architecture - Lesson: Systems architecture: CPU, memory, storage, embedded systems

## Goal
The learner explains the CPU's main components and how they interact via the fetch-execute cycle, factors affecting CPU performance, the different types and purposes of memory, secondary storage (including cloud storage), and embedded systems.

## How to teach this
Ask the learner: when a program is running, where do its instructions actually live while the CPU carries them out, one after another, thousands of times a second? Have the learner predict the output of every Python example before running it, and run code for real whenever they can. #### 3.4.5 Systems architecture: CPU, memory, secondary storage, embedded systems
The **CPU (Central Processing Unit)** carries out (executes) a program's instructions, working with **main memory**, which holds the currently running program and its data. Key CPU components: the **Arithmetic Logic Unit (ALU)** performs arithmetic (e.g. addition) and logical (e.g. comparisons) operations; the **Control Unit (CU)** directs the operation of the whole CPU, coordinating fetching and executing instructions and controlling data flow; the **clock** generates regular electronic pulses that synchronise every part of the CPU's operation, one basic step per pulse; **registers** are tiny, extremely fast storage locations built into the CPU itself, holding data currently being worked on (e.g. the Program Counter holds the address of the next instruction to fetch; the Accumulator holds the result of the ALU's current calculation); **buses** are the physical connections that carry signals between components (e.g. an address bus carries a memory address, a data bus carries the actual data, a control bus carries control signals). The **Fetch-Execute cycle** is the repeating process the CPU uses to run a program: **fetch** the next instruction from the memory address held in the Program Counter, into the CPU; increment the Program Counter to point to the next instruction; **decode** the fetched instruction (work out what it means/what to do); **execute** it (e.g. the ALU performs the required operation); then the cycle repeats for the next instruction. **CPU performance** is affected by: **clock speed** (how many cycles/pulses per second, in Hertz -- a higher clock speed generally means more instructions executed per second); **number of processor cores** (each core can process instructions independently, so more cores can mean more can be done in parallel, though only if the software is written to make use of multiple cores); **cache size** (a small amount of very fast memory built close to/inside the CPU that stores frequently or recently used data and instructions -- a larger cache means more of what's needed is found quickly there rather than fetched from much slower main memory, improving performance). **Memory types**: **RAM** (Random Access Memory) is volatile (loses its contents when power is removed), read/write, and holds the currently running programs and their data; **ROM** (Read-Only Memory) is non-volatile (keeps its contents without power) and holds fixed instructions the computer needs before an operating system is loaded (e.g. start-up/boot instructions); **cache** sits between the CPU and RAM as described above; **registers** are the smallest and fastest of all, inside the CPU itself. **Secondary storage** is needed because RAM is volatile (data would be lost when the computer is switched off) and comparatively small/expensive, so a computer needs somewhere non-volatile to keep files, programs and the operating system permanently: **magnetic** storage (e.g. hard disk drives) uses a spinning disk and a moving read/write head -- large capacity for the cost, but slower and has moving parts that can wear out or fail; **optical** storage (e.g. CD/DVD/Blu-ray) uses a laser to read pits and lands on a reflective disc -- cheap and portable, but lower capacity and can be scratched/damaged; **solid-state** storage (e.g. SSDs, USB flash drives) uses flash memory with no moving parts -- faster and more durable/shock-resistant than magnetic storage, but more expensive per gigabyte and each memory cell has a limited number of write cycles. **Cloud storage** stores data on remote servers, accessed over the internet rather than on a local device: advantages include being accessible from anywhere with an internet connection, automatic offsite backup, and easy scalability without buying local hardware; disadvantages include depending entirely on having a working internet connection, ongoing subscription costs, and having to trust a third party with the security and privacy of the data. An **embedded system** is a computer system built into a larger device to perform one specific, dedicated function (e.g. the controller in a washing machine, a digital thermometer, a car's engine management system) -- unlike a general-purpose computer (e.g. a desktop PC or smartphone), which is designed to run many different applications chosen and changed by the user.
