# S01_Algorithm_Representation - Lesson: Representing algorithms: pseudo-code, flowcharts, decomposition and abstraction

## Goal
The learner explains algorithm, decomposition and abstraction, represents algorithms as pseudo-code, program code and flowcharts, and explains a simple algorithm's inputs, processing, outputs and purpose.

## Syllabus items taught here
- 3.1.1 - Representing algorithms: pseudo-code, program code and flowcharts; decomposition and abstraction

## How to teach this
Ask the learner to write down, step by step, exactly how they make a cup of tea -- that ordered, precise list of steps is an algorithm. Have the learner predict the output of every Python example before running it, and run code for real whenever they can. AQA's own exams are set in AQA's pseudo-code, not any specific language; Python (AQA's widely-used reference teaching language) is used here so examples can be run for real and their output verified, but the learner should also be shown the equivalent pseudo-code form for exam-style tracing questions, since Paper 1 code-reading/writing questions are set in pseudo-code with only the constructs taught in 3.2. Binary/hex conversions, storage and sound/image size calculations, Huffman/RLE compression and logic-gate truth tables were computed/verified when this course was built.

#### 3.1.1 Representing algorithms: pseudo-code, program code and flowcharts; decomposition and abstraction
An **algorithm** is a precise, ordered sequence of steps that solves a problem or completes a task; it is not the same as a program (an algorithm can be written down before any code exists, and the same algorithm can be coded in many languages). **Decomposition** is breaking a large problem into smaller, more manageable sub-problems that are each easier to solve and to combine back into a solution. **Abstraction** is removing unnecessary detail from a problem so only the information relevant to solving it remains (e.g. a London Underground map abstracts away real geography to show only stations and connections). Algorithms are represented in three main ways: **pseudo-code** (structured, code-like English with no fixed syntax, used to plan logic without committing to a language), **program code** (a real language such as Python), and **flowcharts** (diagrams using standard symbols: rounded start/end, rectangle for a process, parallelogram for input/output, diamond for a decision, arrows for flow). Any algorithm can be explained in terms of its **inputs** (data it needs), its **processing** (the steps performed on that data) and its **outputs** (the results produced); from that, its overall **purpose** can be determined even without a written description.
