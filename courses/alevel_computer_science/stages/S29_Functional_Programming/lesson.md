#### 4.12.1.1 Functional programming concepts
In **functional programming**, a function `f` has a **function type**, written `f: A -> B`, meaning it maps every input from type A to an output of type B. A function is a **first-class object**: like any other value, it can be stored in a variable, passed as an argument to another function, or returned as a result from another function. **Function application** means applying a function to its arguments to get a result (e.g. applying `double` to `3` gives `6`). **Partial application** fixes some, but not all, of a function's arguments, producing a new function expecting only the remaining ones (e.g. partially applying a two-argument `add(x, y)` with `x = 5` gives a new one-argument function `add5(y)` that always adds 5). **Composition of functions** builds a new function by feeding one function's output directly into another as its input (e.g. composing `square` then `increment` on 3 gives `increment(square(3))` = `increment(9)` = `10`).

#### 4.12.2.1 Writing functional programs: higher-order functions
Functional programs are typically built from **pure functions** (a function whose result depends only on its inputs, with no side effects on any external/shared state), combined using **higher-order functions**: functions that take another function as an argument, or return one as a result. Three common higher-order functions operating on lists: **map** (applies a given function to every element, producing a new list of the results, e.g. mapping a doubling function over `[3, 7, 2]` gives `[6, 14, 4]`), **filter** (keeps only the elements for which a given predicate function returns True, e.g. filtering `[3, 7, 2, 9]` for evenness gives `[2]`) and **reduce/fold** (combines all the elements of a list into a single value by repeatedly applying a combining function, e.g. reducing `[3, 7, 2, 9]` with addition gives 21). None of map, filter or reduce need an explicitly written loop -- the repetition is handled internally by the higher-order function itself.

#### 4.12.3.1 Lists in functional programming
In functional programming, a **list** is often represented as the combination of a **head** (the first element) and a **tail** (a list of the remaining elements, itself possibly empty) -- so a list can be built up, or taken apart, one element at a time, recursively. A list **can be empty** (the base case for most recursive list-processing functions). Seven common list operations: **return the head** (the first element), **return the tail** (the rest of the list), **test for empty** (does this list have any elements?), **return the length**, **construct an empty list**, **prepend** (add a new element to the front, building a new head-and-tail pair) and **append** (add a new element to the end). *Example* of a recursive length function using head/tail: `length(list)` = 0 if the list is empty; otherwise `1 + length(tail(list))` -- e.g. `length([3, 7, 2])` = `1 + length([7, 2])` = `1 + (1 + length([2]))` = `1 + (1 + (1 + length([])))` = `1 + 1 + 1 + 0` = 3.
