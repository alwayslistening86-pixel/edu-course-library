#### 4.4.4.1 Comparing algorithms; the maths behind Big-O notation
Algorithms solving the same problem can differ hugely in **time complexity** (how the number of steps grows as the input size, n, grows) and **space complexity** (how the memory used grows). Comparing algorithms this way (rather than just timing one run) reveals which scales better to large inputs. The mathematics behind Big-O involves comparing how different types of function grow: **linear** functions (proportional to n), **polynomial** functions (proportional to a power of n, e.g. n²), **exponential** functions (proportional to a constant raised to the power n, e.g. 2ⁿ, which grows explosively), and **logarithmic** functions (proportional to log n, which grows very slowly as n increases) -- plus **permutations** (n!, the number of ways to arrange n items, which grows even faster than exponential).

#### 4.4.4.3 Order of complexity: Big-O notation
**Big-O notation** describes an algorithm's worst-case growth rate, ignoring constant factors and lower-order terms, using the fastest-growing term only. Common classes, fastest to slowest as n grows large: **O(1)** constant (independent of n, e.g. accessing an array by index); **O(log n)** logarithmic (e.g. binary search); **O(n)** linear (e.g. linear search); **O(n log n)** (e.g. merge sort); **O(n²)** polynomial/quadratic (e.g. bubble sort); **O(2ⁿ)** exponential (e.g. checking every subset of n items). An algorithm's Big-O class is found by identifying the operation that dominates as n grows (e.g. nested loops each running n times give O(n²)), and dropping constants (O(3n) is written O(n)) and smaller terms (O(n² + n) is written O(n²)).

#### 4.4.4.4 Limits of computation: tractability, computability and the halting problem
**Tractable** problems can be solved by an algorithm running in **polynomial time** (O(n^k) for some constant k, e.g. O(n), O(n²)) -- feasible even for large n. **Intractable** problems have no known polynomial-time algorithm (only exponential-time or worse solutions are known), so they become impractically slow for even moderately large inputs, even though a solution can theoretically still be found given enough time. Some problems go further: they are **computable** if some algorithm exists that is guaranteed to produce the correct answer in finite time for every valid input (however slow); a problem is **non-computable** if no such algorithm can exist at all, for any amount of time. The classic example is the **halting problem**: can a general algorithm be written that, given any program and its input, always correctly decides whether that program will eventually halt (finish) or run forever? Alan Turing proved this is **non-computable** -- no such general algorithm can ever exist, however cleverly written, however much computing power is available. This matters practically: it means no tool can perfectly, automatically detect every infinite loop in every possible program.

#### 4.4.5.1 The Turing machine
A **Turing machine** is a simple theoretical model of computation: an infinite **tape** divided into cells (each holding a symbol from a fixed alphabet, or blank), a **read-write head** that can read the current cell, write a new symbol to it, and move one cell left or right, and a finite set of **states** with a **transition function** that says, for each (state, symbol read) pair, what symbol to write, which direction to move, and which state to go to next. Despite this extreme simplicity, a Turing machine can (given enough tape and time) compute anything that is computable at all -- this is why it is used as the formal definition of "computable". A **Universal Turing Machine** is a Turing machine that can simulate any other Turing machine, given a description of that machine and its input on the tape -- the theoretical ancestor of the modern general-purpose, program-storing computer. *Simple trace:* a Turing machine that flips every 0 to 1 and every 1 to 0 on the tape, moving right, until it reads a blank: reading '1','0','1' in turn, it writes '0','1','0' respectively, moving right each time, then halts on reaching the blank cell.
