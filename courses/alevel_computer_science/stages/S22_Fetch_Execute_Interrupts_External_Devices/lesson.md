#### 4.7.3.2 The fetch-execute cycle, instruction sets and addressing modes
The **fetch-execute cycle** repeatedly: **fetches** the instruction addressed by the program counter (copy PC's address into the MAR, read memory into the MBR/CIR, and increment the PC ready for next time), **decodes** it (the control unit works out what operation it specifies), then **executes** it (the ALU/other components actually carry it out). A processor's **instruction set** is the fixed collection of machine-code instructions it understands; each instruction has an **opcode** (which operation) and one or more **operands** (the data/addresses the operation works on). **Addressing modes** specify how an operand is interpreted: **immediate addressing** uses the operand's value directly (e.g. "load the literal value 5"); **direct addressing** uses the operand as a memory address to look the actual value up in (e.g. "load the value stored at address 200"). Basic machine-code operations include: load, store, add, subtract, compare, branch (jump, possibly conditionally), logical bitwise operations (AND/OR/etc.), shifts, and halt.

#### 4.7.3.6 Interrupts and factors affecting processor performance
An **interrupt** is a signal (from hardware, e.g. a keypress, or software, e.g. an error) telling the processor to pause its current program and deal with something more urgent. On receiving an interrupt (checked at the end of each fetch-execute cycle), the processor saves its current state, runs an **interrupt service routine (ISR)** to handle the interrupt, then restores its saved state and resumes the interrupted program where it left off -- so, from the fetch-execute cycle's point of view, an interrupt check is added as an extra step at the end of each cycle. Processor **performance** depends on: **clock speed** (more cycles per second, generally faster, though not the only factor); the number of **cores** (separate processing units, allowing genuinely simultaneous execution of multiple instruction streams); **cache memory** (small, very fast memory close to the processor, holding frequently/recently used data so it needn't be fetched from slower main memory each time); and **word length** and **bus width** (how many bits can be processed/transferred at once -- wider means more data moved per cycle).

#### 4.7.4.1 External hardware devices and secondary storage
**External hardware devices** include input devices like **barcode readers** (scan/decode a barcode's pattern into data) and **digital cameras** (capture images as pixel data), output devices like **laser printers** (fuse toner onto paper using a laser-charged drum, fast and high-quality for text/bulk printing), and **RFID (radio-frequency identification)** devices (read/write small tags wirelessly using radio signals, e.g. for contactless access cards or stock tracking). **Secondary storage** is needed because main memory (RAM) is volatile (its contents are lost when powered off) and limited in size; secondary storage devices persist data with power off. **Hard disk drives (HDDs)** use spinning magnetic platters -- large capacity per pound, but slower (mechanical read/write head movement) than **solid-state disks (SSDs)**, which use flash memory with no moving parts -- much faster, especially for random access, but historically more expensive per unit of capacity. **Optical disks** (e.g. DVD, Blu-ray) use a laser to read/write a reflective surface -- cheap and portable, but lower capacity and slower than HDDs/SSDs, well suited to distribution/archival rather than a system's main working storage.
