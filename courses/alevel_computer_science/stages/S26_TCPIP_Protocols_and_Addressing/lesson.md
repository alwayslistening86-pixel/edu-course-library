#### 4.9.4.1 The TCP/IP stack, sockets and MAC addresses
The **TCP/IP model** organises networking into four layers: the **application layer** (protocols used directly by applications, e.g. HTTP, FTP), the **transport layer** (end-to-end delivery between programs, e.g. TCP), the **network layer** (routing packets between networks, e.g. IP) and the **link layer** (transmission over the local physical medium, e.g. Ethernet/WiFi, using **MAC addresses** -- a unique physical address burnt into a network interface, used for local delivery within one network segment). A **socket** is an endpoint for network communication, identified by combining an IP address with a **port number**; it lets the transport layer deliver data to the correct running program on a device, not just to the right device. **Well-known ports** (0-1023, e.g. 80 for HTTP, 443 for HTTPS) are reserved for standard services; **client ports** (ephemeral, temporary, chosen dynamically) are used by the client side of a connection, freed once the connection ends.

#### 4.9.4.2 Standard application-layer protocols
Standard application-layer protocols: **FTP** (File Transfer Protocol, transfers files between an FTP client and server); **HTTP**/**HTTPS** (HyperText Transfer Protocol, and its encrypted form, used by web browsers/servers to request and serve web pages -- a web server serves pages on request, a web browser retrieves and renders them); **POP3** and **SMTP** (retrieving and sending email respectively -- an email server handles both sending and retrieving mail on users' behalf); **SSH** (Secure Shell, used for secure remote management -- an SSH client makes an encrypted TCP connection to a remote server, letting a user log in and execute commands on it securely over an untrusted network).

#### 4.9.4.3 IP addressing, subnetting, DHCP, NAT and port forwarding
An **IP address** splits into a **network identifier** part (identifies which network a device is on) and a **host identifier** part (identifies the specific device within that network). **Subnet masking** divides a network into smaller **subnets**, using a subnet mask to say how many of the address's bits are the network identifier (vs the host identifier) -- letting one large network be split into smaller, more manageable/securable segments. There are two current IP address standards: **IPv4** (32-bit addresses, roughly 4.3 billion possible addresses) and **IPv6** (128-bit addresses, vastly more), introduced because the number of Internet-connected devices eventually exceeded IPv4's available address space. **Public IP addresses** are globally unique and routable directly across the Internet; **private IP addresses** (e.g. within a home/office network) are only unique within their own local network and are not directly routable on the wider Internet. **DHCP** (Dynamic Host Configuration Protocol) automatically assigns an IP address (and other network settings) to a device joining a network, avoiding manual configuration. **NAT** (Network Address Translation) lets many devices on a private network share one public IP address when communicating with the wider Internet, translating between private and public addresses as traffic passes through. **Port forwarding** configures a router to direct incoming traffic on a specific port to a specific device on the private network, letting an external connection reach a service (e.g. a game server) running behind NAT.

#### 4.9.4.10 The client-server model, WebSockets, REST, and thin- vs thick-client computing
The **client-server model** structures communication as clients making requests which servers respond to. **WebSockets** provide a persistent, two-way connection between client and server (unlike a fresh request/response each time), suited to real-time applications (chat, live updates) where either side needs to send data at any moment. **Web CRUD applications** (Create, Read, Update, Delete) expose these four basic data operations over the web; **REST** (Representational State Transfer) is a common architectural style for structuring such web APIs, typically using HTTP methods (GET/POST/PUT/DELETE) to map onto CRUD operations on identified resources. **JSON** (JavaScript Object Notation) and **XML** (eXtensible Markup Language) are both common formats for structuring data exchanged this way; JSON is generally more compact and simpler to read/parse (mapping naturally onto typical programming-language data structures like lists and key-value pairs), while XML's more verbose tag-based structure supports richer document validation/schema features. **Thin-client** computing does most processing on a central server, with the client device doing comparatively little (e.g. mainly displaying results) -- easier to manage/update centrally, but reliant on network connectivity and server capacity; **thick-client** computing does most processing on the client device itself -- more capable offline and less reliant on constant server load, but harder to keep consistently updated across many devices.
