#### 4.9.2.3 Wireless networking
**WiFi** provides wireless networking, typically connecting devices to a wired network via a **wireless access point**. Components needed: a wireless network interface (in each device) and an access point/router. Wireless networks are secured using encryption (e.g. WPA/WPA2/WPA3) and authentication (a network password/key). Because a shared radio channel cannot detect a collision while transmitting (unlike a wired bus), WiFi uses **CSMA/CA** (Carrier Sense Multiple Access with Collision *Avoidance*): a device **listens** to the channel first, and only transmits if it is clear; **without RTS/CTS**, if the channel is clear it transmits directly (still risking a collision if another device transmits at the same instant, undetected -- the "hidden node" problem); **with RTS/CTS** (Request To Send / Clear To Send), the device first sends a short RTS, and the access point replies with CTS, reserving the channel for that device before the actual data is sent, reducing hidden-node collisions. The **SSID (Service Set Identifier)** is the human-readable name identifying a particular wireless network, so a device can choose which network to join.

#### 4.9.3.1 The Internet: packet switching, routers, DNS and URLs
The **Internet** is a global network of interconnected networks. Data is sent using **packet switching**: a message is broken into small **packets**, each containing (among other fields) source/destination addresses, a sequence number (so they can be reassembled correctly) and the data payload; packets can travel independently, potentially by different routes, and are reassembled at the destination. **Routers** examine each packet's destination address and forward it towards its destination, hop by hop, across the network; a **gateway** connects two different networks (e.g. a home network to the wider Internet), often performing address translation. A **URL (uniform resource locator)** identifies a specific resource's location and how to access it (e.g. `https://www.example.com/page.html`). A **domain name** (e.g. `example.com`) is a human-readable name for a server, organised hierarchically (a **fully qualified domain name, FQDN**, like `www.example.com`, names a specific host within that domain); the **Domain Name System (DNS)**, a distributed hierarchy of servers, translates domain names into the numeric **IP addresses** that routers actually use to forward packets; **Internet registries** allocate and manage blocks of IP addresses and domain names globally, so they remain unique.

#### 4.9.3.2 Internet security
A **firewall** controls traffic entering/leaving a network, using techniques such as **packet filtering** (allowing/blocking packets by rules on their address/port), a **proxy server** (relays requests on a client's behalf, hiding its true address and allowing inspection/filtering), or **stateful inspection** (tracks the state of active connections, only allowing traffic that is part of a legitimate, already-established exchange). **Symmetric encryption** uses the same secret key to encrypt and decrypt (fast, but the key must somehow be shared securely first); **asymmetric (public/private key) encryption** uses a mathematically linked key pair -- data encrypted with the public key (which can be shared openly) can only be decrypted with the matching private key (kept secret), solving the key-sharing problem, though it is slower, so is often used just to securely exchange a symmetric key for the rest of a session. A **digital certificate** (issued by a trusted certificate authority) binds a public key to an identity (e.g. a website), letting a user verify they are really communicating with who they think; a **digital signature** uses the sender's private key to prove a message genuinely came from them and was not altered. **Worms** self-replicate and spread across a network without needing a host file or user action; **trojans** disguise themselves as legitimate software to trick a user into installing them; **viruses** attach themselves to a host file/program and spread when that host is run/shared; all exploit vulnerabilities such as unpatched software or users being tricked into risky actions -- addressed by improved code quality (fewer exploitable bugs), monitoring (detecting unusual activity) and protective software (e.g. antivirus, firewalls).
