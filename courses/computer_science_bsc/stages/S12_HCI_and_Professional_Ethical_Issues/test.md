# S12_HCI_and_Professional_Ethical_Issues - Test: Human-computer interaction and professional/ethical issues

## How to run this
A real checkpoint in the style of OU-module-level questions: structured problems, code-trace/code-output items, multiple-select conceptual items and, where the topic is genuinely discursive (professional/ethical/HCI content), extended-response items marked on levels. Give the whole test at once, with no hints; the learner shows full working/code. Then mark against the mark schemes below and this stage's entry in `rubric.json`.

## Test items
1. A checkout page shows no indication that a payment is processing after the user clicks 'Pay Now', leading many users to click it repeatedly. Name the Nielsen heuristic this violates and explain the fix in terms of that heuristic. [3 marks]
2. An e-commerce site uses low-contrast grey text on a white background and relies entirely on colour (red/green) to show whether an item is in or out of stock, with no text label. Identify two distinct WCAG/accessibility failures here and state which WCAG principle each falls under. [4 marks]
3. Explain the difference between the Computer Misuse Act 1990's offence of unauthorised access and unauthorised modification, using an example of each. [4 marks]
4. Under UK GDPR's data minimisation principle, explain what is wrong with an app that requests access to a user's full contact list and precise location history in order to offer a simple currency-conversion feature. [3 marks]
5. A company proposes deploying a facial-recognition system in a shopping centre to identify known shoplifters automatically, without shoppers' individual consent. Discuss the ethical and professional issues this raises, applying at least one consequentialist and one deontological consideration, and referring to the BCS Code of Conduct's public-interest duty. [20 marks]

## Answer key (for the tutor only)
1. [3] B1 visibility of system status; B1 the system gives the user no feedback that their action was received and is being processed, so the user reasonably assumes nothing happened and repeats the action; B1 fix: show an immediate, visible status indicator (e.g. a spinner or disabled button with 'Processing...') the moment the action is triggered, keeping the user informed throughout.
2. [4] B2 insufficient colour contrast, failing the Perceivable principle (text must be presentable/legible; WCAG specifies a minimum contrast ratio) (B1 if only 'contrast' named without linking to Perceivable); B2 conveying stock status by colour alone excludes colour-blind users and anyone using a non-colour assistive technology, also failing Perceivable (information must not rely on colour alone to convey meaning) -- credit if the learner instead links this second failure to Understandable with a coherent justification (B1 if only 'colour-only' named without the WCAG-principle link).
3. [4] B1 unauthorised access: intentionally accessing a computer/data without permission, regardless of whether anything is changed, e.g. logging into an account using a stolen or guessed password just to look at private data; B1 unauthorised modification: intentionally, and without authorisation, altering data/programs/the operation of a computer, e.g. deploying ransomware that encrypts a victim's files, or defacing a website; B1 both require the act to be unauthorised and (for the basic offence) the person to know it is unauthorised; B1 valid, distinct examples given for each offence.
4. [3] B1 data minimisation requires collecting only the personal data that is actually necessary for the stated purpose; B1 a currency-conversion feature has no genuine need for the user's contacts or precise location history, so collecting them is disproportionate to the purpose; B1 this both breaches the data minimisation principle and creates unnecessary privacy risk (a larger amount of sensitive data held than the feature requires, increasing the harm of any future breach).
5. [20] Mark out of 20 using honours-level (RQF Level 6) discursive levels, per the QAA Computing benchmark's expectation that graduates can 'engage with fundamental, legal, social, ethical and professional issues': Level 1 (1-4) states a position with little justification or named concept/framework; Level 2 (5-9) identifies relevant concepts/frameworks but applies them only descriptively, with limited weighing of alternatives; Level 3 (10-14) applies named concepts/frameworks (e.g. a specific ethical framework, professional code clause, or legal provision) accurately to the scenario and weighs at least one genuine counter-consideration; Level 4 (15-17) a well-structured argument that applies multiple relevant frameworks correctly, explicitly weighs competing considerations, and reaches a justified, nuanced conclusion; Level 5 (18-20) a sophisticated answer that additionally identifies tensions between frameworks or stakeholders the question does not spell out, and sustains a precise, fully justified judgement throughout. Credit specifically: a consequentialist case (net public-safety/loss-prevention benefit versus the harm of surveillance/false-match misidentification, especially given documented higher false-match rates for some demographic groups); a deontological case (a duty to respect individual privacy and obtain informed consent, which blanket, non-consensual surveillance of every shopper violates regardless of aggregate benefit); the BCS Code of Conduct's public-interest duty (having regard to the public's privacy and legitimate rights, not just the client's commercial interest); UK GDPR-relevant concerns (biometric data is a special category of personal data attracting stricter protection, and processing it without a clear lawful basis/consent is legally problematic, not only ethically); a strong answer weighs these considerations against each other rather than only listing them.
